# Мост Claude ↔ 1С: инструкция для программиста

## Зачем это

Сейчас Claude вносит правки в 1С мышью через RDP: открывает дерево, вставляет код через буфер, жмёт F7, «Обновить конфигурацию БД» и делает десятки скриншотов на каждый шаг. Это медленно, дорого (около половины всех токенов за месяц) и ненадёжно.

Мост убирает клики. Claude готовит правку **в файлах**. Сервер раз в минуту сам забирает задания из приватного git-репозитория, выполняет их **Конфигуратором в пакетном режиме** (без окон) и возвращает текстовый лог.

```
Claude ──push──► приватный GitHub-репозиторий ◄──pull/push── сервер 1С (bridge.ps1, раз в минуту)
                                                                 │
                                                 1cv8.exe DESIGNER … /LoadConfigFromFiles …
                                                 (без окон, результат в текстовом логе)
```

- **Входящие порты не нужны.** Сервер только сам ходит наружу (GitHub и Telegram). После запуска моста порт RDP 44000 можно закрыть от интернета.
- **Сервер выполняет только белый список действий** и только для расширений, перечисленных в `config.json`.
- **Копия (`UNF_copy`)** меняется по заданию автоматически, с бэкапом `.cfe` перед каждой загрузкой.
- **Рабочая база** меняется только после команды `/ok_<id>` от Сергея в Telegram и только в вечернее окно. Перед выкаткой мост проверяет, что расширение в рабочей базе никто не менял после ночной выгрузки. Если меняли, выкатка останавливается.

## Что в комплекте

| Файл | Что это |
|---|---|
| `bridge.ps1` | Скрипт моста (PowerShell 5.1, сохранён в UTF-8 с BOM, **не пересохранять в другой кодировке**) |
| `config.example.json` | Шаблон настроек: пути, базы, пользователи, расширения, Telegram |
| `repo-template/` | Начальное содержимое репозитория-ящика (`.gitattributes`, папки заданий, правила для Claude) |

Скрипт прогнан на тестовом стенде с имитацией 1С: выгрузка, загрузка в копию, сборка epf, отклонение недопустимых заданий, выкатка с подтверждением, остановка при чужих правках. **На настоящей 1С он ещё не запускался**, поэтому первый запуск делаем вместе и только на копии (шаг 6).

## Шаг 1. Репозиторий-ящик (делает Сергей или Claude)

1. Создать **приватный** репозиторий на GitHub, например `alimovpr/1c-bridge`.
2. Положить в него содержимое `repo-template/` (ветка `main`).

Туда попадает только **код конфигурации**, данные из базы туда не попадают.

## Шаг 2. Пользователи

**Windows:** создать локального пользователя `1c-bridge`. Он не администратор и без права входа по RDP.

**1С:**
- в копии `UNF_copy` — пользователь `Claude` с правами на запуск Конфигуратора и администрирование;
- в рабочей базе — пользователь `Claude_deploy` с правами на запуск Конфигуратора. Его пароль хранится **только** в `config.json` на сервере, Claude его не знает.

## Шаг 3. Установка на сервер 1С

1. Установить **Git for Windows**.
2. Создать папку `C:\1cb`. Короткий путь выбран специально: в выгрузке 1С длинные пути.
3. Выдать права NTFS на `C:\1cb` только пользователю `1c-bridge` и администраторам.
4. Положить в `C:\1cb` файл `bridge.ps1`.
5. Скопировать `config.example.json` в `C:\1cb\config.json` и заполнить:
   - путь к `1cv8.exe` (8.5.1.1343);
   - имена баз в кластере;
   - пользователей и пароли;
   - **список расширений**, которые мосту разрешено трогать.
6. Ключ доступа к репозиторию (от имени `1c-bridge`):
   ```powershell
   ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\id_ed25519 -N '""'
   ```
   Публичный ключ (`id_ed25519.pub`) добавить в репозиторий: *Settings → Deploy keys → Add*, **Allow write access**.
   Если исходящий порт 22 закрыт, в `~\.ssh\config` добавить:
   ```
   Host github.com
     HostName ssh.github.com
     Port 443
   ```
7. Клонировать репозиторий и настроить git:
   ```powershell
   git config --global core.longpaths true
   git config --global user.name  "1C bridge"
   git config --global user.email "bridge@local"
   git clone git@github.com:alimovpr/1c-bridge.git C:\1cb\repo
   git -C C:\1cb\repo config core.autocrlf false
   ```

## Шаг 4. Telegram

1. В @BotFather создать **нового** бота (например, «1С мост»). Бот Джони не подходит: два процесса не могут читать одного бота.
2. Записать токен в `config.json` → `Telegram.Token`.
3. Сергей пишет новому боту `/start`. После этого его id видно по ссылке `https://api.telegram.org/bot<ТОКЕН>/getUpdates` в поле `message.from.id`. Записать его в `Telegram.ChatId`.

Мост принимает команды **только** от этого id.

## Шаг 5. Первый ручной запуск: ночная выгрузка

От имени `1c-bridge`:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\1cb\bridge.ps1 -Nightly
```

Что проверить:
- в репозитории на GitHub появились `src/cf/` и `src/ext/<ИмяРасширения>/`;
- в `jobs/done/nightly.log` нет ошибок;
- `-AllExtensions` разложил расширения по подпапкам с их именами;
- текст в логе читается нормально, кракозябр нет. Если есть — сообщите, поправим кодировку чтения.

Первая выгрузка полная, это может занять время. Дальше основная конфигурация выгружается только изменениями (`-update`).

## Шаг 6. Проверка на копии (вместе с Claude)

Claude по очереди положит в `jobs/inbox/` три задания. Вы запускаете скрипт вручную (без `-Nightly`) и смотрите результат в `jobs/done/`:
1. `check-copy` — только проверка модулей;
2. `load-copy` из `main` без изменений — бэкап, загрузка, обновление БД, проверка;
3. `load-copy` с небольшой реальной правкой — проверяем её в копии.

Если какой-то ключ командной строки на 8.5 называется иначе, это будет видно в логе. Поправим в `bridge.ps1`, все вызовы 1С собраны в функциях `Do-*`.

## Шаг 7. Планировщик Windows

```powershell
$user = '.\1c-bridge'; $pass = 'ПАРОЛЬ_ПОЛЬЗОВАТЕЛЯ_WINDOWS'
$s = New-ScheduledTaskSettingsSet -MultipleInstances IgnoreNew -ExecutionTimeLimit (New-TimeSpan -Hours 3)

# Раз в минуту — разбор заданий
$a = New-ScheduledTaskAction -Execute powershell.exe -Argument '-NoProfile -ExecutionPolicy Bypass -File C:\1cb\bridge.ps1'
$t = New-ScheduledTaskTrigger -Once -At (Get-Date) -RepetitionInterval (New-TimeSpan -Minutes 1) -RepetitionDuration (New-TimeSpan -Days 3650)
Register-ScheduledTask '1C bridge' -Action $a -Trigger $t -Settings $s -User $user -Password $pass

# Каждую ночь в 3:00 — свежая выгрузка рабочей базы
$a2 = New-ScheduledTaskAction -Execute powershell.exe -Argument '-NoProfile -ExecutionPolicy Bypass -File C:\1cb\bridge.ps1 -Nightly'
$t2 = New-ScheduledTaskTrigger -Daily -At 3:00
Register-ScheduledTask '1C bridge nightly' -Action $a2 -Trigger $t2 -Settings $s -User $user -Password $pass
```

Если Windows ругается на `-RepetitionDuration`, уберите этот параметр или в окне Планировщика поставьте у триггера «Повторять каждую минуту — бесконечно».

Если в фоновом режиме («выполнять независимо от входа пользователя») Конфигуратор зависает или не стартует, переключите задачи в режим «только при входе пользователя» под `1c-bridge`.

## Шаг 8. Закрыть порт 44000

Когда мост проработал несколько дней, закрыть RDP от интернета: доступ только через VPN или по белому списку IP. Мосту этот порт не нужен.

## Шаг 9 (по желанию). Веб-клиент для копии

Чтобы Claude проверял сценарии в Предприятии через браузер, а не через RDP, опубликуйте **`UNF_copy`** с включённым веб-клиентом (рядом с текущей публикацией на `:9876`).
- Тестовый пользователь должен быть только в копии.
- Доступ только через VPN или белый список.

Браузер Claude читает страницу как текст: поля, кнопки, таблицы. Скриншоты и задержка картинки не нужны.

## Что умеет мост

| Действие | Где | Что делает |
|---|---|---|
| `check-copy` | копия | проверка модулей расширения (`/CheckModules`) |
| `load-copy` | копия | `/DumpCfg` (бэкап) → `/LoadConfigFromFiles` → `/UpdateDBCfg` → `/CheckModules` |
| `build-epf` | — | `/LoadExternalDataProcessorOrReportFromFiles`, готовый `.epf` в `C:\1cb\out` и в `out/` репозитория |
| `dump-prod` | рабочая (чтение) | `/DumpConfigToFiles` основной конфигурации и расширений в `src/` |
| `deploy-prod` | рабочая | проверка чужих правок → бэкап → загрузка → обновление → проверка → свежая выгрузка в `src/ext` |

Бэкапы лежат в `C:\1cb\backups`, журнал работы в `C:\1cb\bridge.log`, состояние подтверждений в `C:\1cb\state.json`.

## Безопасность коротко

- Произвольные команды выполнить нельзя: только 5 действий, только разрешённые расширения, имена веток и обработок проверяются.
- Пароли 1С хранятся только в `config.json` на сервере и не попадают в git.
- Рабочая база меняется только после `/ok_<id>` от Сергея и только в окне `DeployWindow`.
- Перед каждой загрузкой делается бэкап расширения. Откат: загрузить `.cfe` из `C:\1cb\backups`.
- Ключ GitHub даёт доступ только к одному репозиторию.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| Ошибка «конфигурация заблокирована» или «захвачена» | В копии открыт Конфигуратор (Ирина или вы). Закрыть и повторить задание |
| `UpdateDBCfg` в рабочей базе требует монопольный режим | Поэтому выкатка только вечером. При необходимости сдвинуть `DeployWindow` |
| Ключ командной строки не распознан | Лог покажет, какой. Поправить вызов в `bridge.ps1` |
| В логах кракозябры | Сообщить Claude, поменяем кодировку чтения `/Out` |
| В Telegram пишет «Мост 1С: ошибка» | Подробности в `C:\1cb\bridge.log` |
