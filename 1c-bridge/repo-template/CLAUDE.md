# Работа с 1С через мост

Этот репозиторий — «почтовый ящик» между Claude и сервером 1С. В 1С не заходим через RDP и не кликаем:
всё делается файлами и заданиями, сервер выполняет их сам в пакетном режиме и возвращает текстовый лог.

## Что где лежит

- `src/cf/` — выгрузка основной конфигурации **рабочей** базы (обновляется каждую ночь, только чтение).
- `src/ext/<Имя>/` — выгрузка расширений рабочей базы (каждую ночь и после каждой выкатки).
- `epf/<Имя>/<Имя>.xml` — исходники внешних обработок.
- `jobs/inbox/` — сюда кладём задания. `jobs/done/` — сюда сервер кладёт результат с логом.
- `out/` — собранные `.epf`.

## Как сделать правку

1. `git pull`, затем ветка от свежего main: `git checkout -b task/<NNN> origin/main`.
2. Правим файлы в `src/ext/<Имя>/` (или `epf/`). **Сохраняем кодировку и переводы строк как в файле** (UTF-8 с BOM, CRLF) — иначе 1С не загрузит.
3. `git push origin task/<NNN>`.
4. Кладём задание в `jobs/inbox/<id>.json` на ветке **main** и пушим:
   ```json
   {"id": "020", "action": "load-copy", "ext": "ИмяРасширения", "ref": "task/020", "note": "что и зачем"}
   ```
5. Ждём (сервер проверяет ящик раз в минуту), `git pull`, читаем `jobs/done/<id>.json`: `ok` и `log`.

`id` — только латиница и цифры (используется в команде `/ok_<id>` в Telegram).

## Какие задания понимает сервер

| action | поля | что делает |
|---|---|---|
| `check-copy` | `ext` | проверка модулей расширения в копии |
| `load-copy` | `ext`, `ref` | бэкап → загрузка из ветки в UNF_copy → обновление БД → проверка модулей |
| `build-epf` | `name`, `ref` | собирает `.epf` из `epf/<name>/<name>.xml`, кладёт в `out/` |
| `dump-prod` | — | внеочередная выгрузка рабочей базы в `src/` |
| `deploy-prod` | `ext`, `ref` | выкатка в **рабочую** базу — только после `/ok_<id>` от Сергея в Telegram и только в вечернее окно |

Другие действия и расширения не из `config.json` сервер отклоняет.

## Правила

- Проверяем **только на копии** (`load-copy`). Результат смотрим через **OData** копии, а не через экран.
- `deploy-prod` ставим только когда Сергей сказал «выкатываем». Сервер всё равно спросит подтверждение в Telegram.
- Если выкатка отклонена с «расширение в рабочей базе отличается» — кто-то правил его руками: делаем `dump-prod`, переносим правку на свежую выгрузку и снова проверяем на копии.
- В рабочей базе Claude ничего не меняет в обход моста.
